<objective>
Wire the CLI escape hatch: a `Ctrl+R` intercept at the very TOP of `handle_key`,
ABOVE the `pending_input` routing block (deliberate, documented D-07 never-discard
exception), opening a two-tier status-bar prompt:

`Reset:  [s] soft   [f] full (MEMORY LOST)   [Esc] cancel`

`s` → `state.soft_reset()` + persist. `f` → `MEMORY LOST? [y/n]`; `y` →
`state.memory_lost()` + persist. Esc/`n`/any other key → cancel. The reset also
clears CLI-only transient state (`shift_armed`, any in-progress entry) that never
lives in `CalcState`.

**BLOCKING PRECONDITION — `Ctrl+R` conflict:** `Ctrl+R` is ALREADY bound at
`hp41-cli/src/app.rs:634` to `Op::Rdprgm` (Card Reader "read program" comfort
shortcut). The escape hatch MUST win. Task 1 resolves this conflict explicitly
(see action) — do not wire reset without first relocating/removing the Rdprgm
binding or the intercept order makes Ctrl+R ambiguous.

Purpose: terminal recovery from any stuck state. Output: a reset state machine in app.rs.
</objective>
