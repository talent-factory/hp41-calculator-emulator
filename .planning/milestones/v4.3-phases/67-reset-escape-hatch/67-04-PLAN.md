<objective>
Wire the GUI/iOS `ON` key as the escape hatch, OUTSIDE the normal
`handleClick`/`key_map.resolve()` path (the ON key has `id: ''` and currently
no-ops at `handleKeyClick`'s `if (!key.id) return`). Tap = `invoke('reset_soft')`;
long-press (~600 ms, mouse-hold + touch) = open a `createPortal`-ed confirmation
sheet ("MEMORY LOST — delete all programs, registers and files?") → on confirm,
`invoke('reset_full')`. The pointer-up that ends a long-press must NOT fire the
soft reset. On reset, clear frontend-only transient state (`shiftActive`,
in-progress ALPHA, any waiting-for-key UI). Refresh the view from the returned
`CalcStateView`.

Purpose: cross-frontend recovery (desktop + iOS) with parity to the CLI Ctrl+R.
Output: ON-key handler + portaled confirm sheet + vitest coverage. The plan is
non-autonomous because the on-device long-press feel + portal rendering (sheet
not clipped by the CSS scale transform) need one human-verify pass.
</objective>
