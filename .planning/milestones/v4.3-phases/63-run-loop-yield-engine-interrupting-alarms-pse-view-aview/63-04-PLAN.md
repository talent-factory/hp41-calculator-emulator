<objective>
GUI continuous-program-execution backend (the big add): expose the core run loop to the GUI via two thin Tauri commands — `run_program` (start a label program) and `resume_program` (continue after a yield/stop) — each a few lines of glue around `hp41_core::ops::program::{run_program,resume_program}`, register them in `generate_handler!`, add their permission TOMLs + capability references, and project `pending_yield` through `CalcStateView`. Until this plan, the GUI had NO continuous program run loop: `handle_run_stop` (commands.rs:476) only toggled `is_running` and no `run_program`/`run_loop`/`resume_program` call existed anywhere in `hp41-gui/src-tauri/src/`. This plan makes the GUI able to run user-LBL programs to CLI parity, which is what unlocks GUI criteria 1/4/5.

Purpose: The GUI run-loop driver (63-06, TS) cannot exist until these commands are invokable. This plan is the Rust half of the GUI track — pure glue (SC-4: the run_loop logic lives in hp41-core from 63-02; the GUI adds zero calculator logic). Mutex is released between each command return (D-01/D-11): each `invoke('run_program')`/`invoke('resume_program')` locks, runs the core loop until it BREAKS at a yield/stop/end/error, returns, and releases — so the GUI stays responsive between yields.
Output: Two invokable Tauri commands + pending_yield projection; the GUI can drive continuous program execution from TS.

Touches GUI-Rust files ONLY (`commands.rs`, `types.rs`, `lib.rs`, `permissions/*.toml`, `capabilities/default.json`) — disjoint from 63-03 (CLI `app.rs`), 63-05 (docs), and 63-06 (App.tsx/App.test.tsx). Safe to run parallel in Wave 3 alongside 63-03 and 63-05. 63-06 (TS driver) depends on this plan (the commands must exist before TS can invoke them).
</objective>
